# توثيق مساجد مكتب أوقاف القره بوللي

تطبيق ويب عربي (RTL) مخصص للهاتف أولاً والحاسوب، يمكّن موظفي مكتب أوقاف القره بوللي من توثيق المساجد ميدانياً، وحفظ الإحداثيات وصور العلامات الدالة في **Firebase Firestore** مع العمل دون إنترنت، ثم تصدير البيانات إلى ملف **Excel** بقالب المكتب الرسمي.

---

## المميزات الأساسية
- **توثيق ميداني سريع من الهاتف**: خريطة تفاعلية (OpenStreetMap مع زر تبديل للقمر الصناعي Esri World Imagery)، تحديد الموقع عبر GPS عالي الدقة مع عرض الدقة بالمتر وتنبيه ضعف الإشارة (> 30 م)، وسحب الدبوس لتثبيت الموقع بدقة.
- **منع التكرار الذكي**: التحقق التلقائي من تطابق الاسم أو القرب الجغرافي (أقل من 30 متراً) مع خيار تعديل السجل الموجود أو الحفظ كمسجد مختلف.
- **ضغط الصور دون تكلفة تخزين إضافية**: ضغط حتى 3 صور للعلامة الدالة في المتصفح (عرض 1000 بكسل، صيغة JPEG جودة 0.7) وحفظها داخل سجل المسجد في Firestore ضمن الحد الآمن (< 900 كيلوبايت) دون الحاجة إلى Firebase Storage.
- **العمل دون إنترنت (Offline Persistence)**: حفظ السجلات محلياً عند انقطاع الإنترنت ومزامنتها تلقائياً عند عودة الاتصال، مع مؤشر واضح للحالة (`متصل` / `غير متصل`).
- **الخريطة العامة**: عرض جميع المساجد الموثقة مع التجميع التلقائي للدبابيس المتقاربة وبطاقة تفاصيل تتضمن الصور وزر الفتح والاتجاهات في خرائط جوجل.
- **قائمة المساجد والتصدير إلى Excel**: بحث بالاسم وفلترة بالمحلة، وتصدير للمدير عبر مكتبة SheetJS (`xlsx-js-style`) بقالب عربي RTL مطابق للأعمدة المطلوبة مع روابط قابلة للنقر.
- **صلاحيات واضحة**:
  - **موثِّق**: يضيف مساجد جديدة، ويعدّل ويحذف ما أضافه هو فقط.
  - **مدير**: يطّلع على جميع السجلات، ويعدّل ويحذف ويصدّر Excel ويضيف حسابات الموثِّقين.

## التشغيل المحلي

1. **تثبيت الحزم:**
   ```bash
   npm install
   ```

2. **تشغيل بيئة التطوير:**
   ```bash
   npm run dev
   ```

3. **بناء نسخة الإنتاج:**
   ```bash
   npm run build
   ```

## إعداد Firebase
1. تأكد من وجود ملف `firebase-applet-config.json` في جذر المشروع محتوياً على بيانات مشروعك (`projectId`, `apiKey`, `authDomain`, `appId`, `firestoreDatabaseId`).
2. **تفعيل تسجيل الدخول بالبريد وكلمة المرور**:
   - من لوحة تحكم Firebase افتح **Authentication > Sign-in method**.
   - فعّل مزوّد **Email/Password** (لا تفعّل التسجيل الذاتي في الواجهة؛ الحسابات تُنشأ من المدير فقط).
3. **إنشاء حساب المدير الأول**:
   - من **Authentication > Users** أضف مستخدماً جديداً بالبريد الإلكتروني وكلمة المرور.
   - في **Firestore Database** أنشئ مستنداً داخل المجموعة `users` يكون معرفه (Document ID) هو نفسه `UID` الخاص بالمدير، ويحتوي الحقول التالية:
     - `uid`: معرف المستخدم (String)
     - `name`: اسم المدير (String)
     - `email`: البريد الإلكتروني (String)
     - `role`: `"admin"` (String)
     - `createdBy`: معرف المستخدم (String)
     - `createdAt`: طابع زمني (Timestamp)
4. **نشر قواعد الأمان (`firestore.rules`)**:
   - انشر ملف `firestore.rules` المرفق لحماية مجموعة `mosques` و`users` بحيث لا يقرأ ولا يكتب غير الموظفين المسجلين، ولا يعدّل الموثِّق أو يحذف إلا سجلاته الخاصة.
